# 3. Authentication vs Authorization

These two concepts are constantly confused.

Understanding them properly is critical.

---

# Authentication

Authentication answers:

```text
Who Are You?
```

Examples:

```text
Username + Password

Access Key + Secret Key

SSO Login
```

Think:

```text
Identity Verification
```

Example:

```text
You say:
I am Maaz

AWS asks:
Prove it
```

Authentication is proving identity.

---

# Authorization

Authorization answers:

```text
What Can You Do?
```

Example:

```text
Can Create S3 Bucket?
Can Delete EC2?
Can Access SageMaker?
```

Authentication:

```text
Who Are You?
```

Authorization:

```text
What Are You Allowed To Do?
```

---

# Real Life Example

Airport Example

Authentication:

```text
Show Passport
```

Authorization:

```text
Can Enter VIP Lounge?
```

Different concepts.

---

# AWS IAM Handles Both

IAM manages:

```text
Identity
+
Permissions
```

---

# 5. IAM User

An IAM User represents:

```text
A Person
An Application
A Service Account
```

Example:

```text
Maaz
```

could be an IAM User.

---

# Why Not Use Root Account?

AWS account creation generates:

```text
Root User
```

This user has:

```text
Unlimited Power
```

Can:

```text
Delete Everything
Close Account
Delete Resources
Modify Billing
```

This is dangerous.

Industry rule:

```text
Never Use Root Account Daily
```

Use IAM Users instead.

---

# Our Project

What did we do?

We created:

```text
IAM User
```

Then:

```text
Access Key
Secret Key
```

Then:

```bash
aws configure
```

This is exactly how IAM integrates with AWS CLI.

```text
100 Data Scientists
```

Should we assign permissions individually?

Instead:

```text
DataScientists Group
```

Example:


Add users to group.

Done.

# Benefits

Instead of:

```text
100 Permission Assignments
```


Much easier.

# 7. IAM Policy

Policy is the most important IAM concept.

Policy defines:

```text
Permissions
```

Policy answers:

```text
Allowed?
Denied?
```

---

# Example Policy

Conceptually:

```json
{
  "Allow": "S3Read"
}
```

Meaning:

```text
Can Read S3
```

---

# AWS Policies Are JSON Documents

AWS uses JSON because it is:

```text
Structured
Readable
Machine Friendly
```

---

# Example Real Policy

```json
{
  "Version":"2012-10-17",
  "Statement":[
    {
      "Effect":"Allow",
      "Action":"s3:*",
      "Resource":"*"
    }
  ]
}
```

Interpretation:

```text
Allow
All S3 Actions
On All Resources
```

Very powerful.

---

# 8. Least Privilege Principle

One of the most important security principles.

Never give:

```text
Maximum Access
```

Give:

```text
Minimum Required Access
```

Example:

Bad:

```text
S3 Full Access
```

if user only uploads files.

Better:

```text
S3 PutObject
S3 GetObject
```

only.

---

# Industry Rule

Always follow:

```text
Least Privilege
```

because:

```text
Less Permission
↓
Less Damage
```

---

# 9. IAM Role

Roles confuse beginners.

Let's simplify.

User:

```text
Permanent Identity
```

Role:

```text
Temporary Permission Set
```

---

# Example

EC2 needs access to S3.

Should we store:

```text
Access Key
Secret Key
```

inside EC2?

Bad practice.

Instead:

```text
Attach IAM Role
```

to EC2.

AWS automatically provides credentials.

---

# This Is Huge

Later:

```text
EC2
↓
S3

SageMaker
↓
S3

Lambda
↓
S3
```

will all use Roles.

Not access keys.

---

# 10. Access Key and Secret Key

When we configured:

```bash
aws configure
```

AWS asked:

```text
Access Key
Secret Key
```

Why?

Because AWS CLI must authenticate.

Think:

```text
Username
Password
```

but for programmatic access.

---

# Never Share Secret Key

If leaked:

```text
Attacker Can Use AWS
```

Potential consequences:

```text
Huge Bills
Deleted Resources
Security Breach
```

Treat Secret Keys like passwords.

---

# 11. How AWS CLI Actually Works

When you run:

```bash
aws s3 ls
```

AWS CLI:

Step 1:

```text
Read Credentials
```

Step 2:

```text
Send Request To AWS
```

Step 3:

```text
IAM Evaluates Permissions
```

Step 4:

```text
Allow
or
Deny
```

Step 5:

```text
Return Response
```

Everything passes through IAM.

---

# 12. Permission Evaluation Logic

AWS effectively asks:

```text
Do You Have Permission?
```

If:

```text
Allow
```

request succeeds.

If:

```text
Deny
```

request fails.

---

# Important Rule

Explicit Deny always wins.

Even if another policy says:

```text
Allow
```

Explicit Deny overrides.

# 16. Interview Questions

Q1. What is IAM?

Answer:

AWS service that manages authentication and authorization.

---

Q2. Difference between Authentication and Authorization?

Authentication:

Who are you?

Authorization:

What can you do?

---

Q3. Why should you avoid using Root User?

Because it has unrestricted access and increases risk.

---

Q4. What is Least Privilege?

Granting only the permissions required to perform a task.

---

Q5. Difference between IAM User and IAM Role?

User:

Permanent identity.

Role:

Temporary permissions that can be assumed.

---

Q6. Why do EC2 instances commonly use IAM Roles?

To securely access AWS services without storing credentials.

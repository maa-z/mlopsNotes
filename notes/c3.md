# Chapter 3 — Amazon S3 Deep Dive

# 1. Why S3 Matters

If IAM is the security foundation of AWS,

then S3 is the storage foundation.

Almost every MLOps workflow touches S3.

Examples:

```text
Datasets
Models
Artifacts
Logs
Backups
Feature Files
Training Outputs
```

In our project:

```text
Local Dataset
↓
S3

S3
↓
EC2

Trained Model
↓
S3

Artifacts
↓
S3
```

Without S3, our entire workflow breaks.

---

# 2. What Is S3?

S3 stands for:

```text
Simple Storage Service
```

S3 is an Object Storage Service.

This is one of the most important concepts in AWS.

Many beginners think:

```text
S3 = Hard Drive
```

Wrong.

S3 is not a traditional filesystem.

S3 is Object Storage.

---

# 3. Types of Storage

There are three major storage types.

---

## Block Storage

Example:

```text
EBS
SSD
Hard Drive
```

Looks like:

```text
Disk
↓
Partitions
↓
Files
```

Operating systems love block storage.

EC2 disks use block storage.

---

## File Storage

Example:

```text
Network File Systems
```

Looks like:

```text
Folders
↓
Subfolders
↓
Files
```

Traditional company file servers work this way.

---

## Object Storage

Example:

```text
Amazon S3
```

Looks like:

```text
Bucket
↓
Objects
```

No real folders.

This is S3.

---

# 4. Bucket

Bucket is the top-level container.

Think:

```text
Bucket
=
Storage Container
```

Example:

```text
maaz-animal-classifier-01
```

This is our bucket.

---

# Important Rule

Bucket names must be globally unique.

Why?

Because:

```text
AWS
↓
One Global Namespace
```

If someone already created:

```text
my-bucket
```

You cannot use it.

---

# 5. Object

Inside a bucket we store objects.

Object consists of:

```text
Data
+
Metadata
+
Object Key
```

Example:

```text
cat.jpg
```

is an object.

---

# 6. Object Key

This is where many beginners get confused.

Suppose we have:

```text
s3://maaz-animal-classifier-01/dataset/Cat/cat1.jpg
```

Break it down:

Bucket:

```text
maaz-animal-classifier-01
```

Object Key:

```text
dataset/Cat/cat1.jpg
```

---

# Important Realization

There is NO actual folder.

AWS stores:

```text
dataset/Cat/cat1.jpg
```

as a single string.

Folders are an illusion.

---

# What Actually Exists?

Not:

```text
dataset
└── Cat
    └── cat1.jpg
```

Internally:

```text
dataset/Cat/cat1.jpg
```

one object key.

---

# Why Does AWS Show Folders?

For human convenience.

Console creates folder-like views.

But internally:

```text
Prefix Matching
```

creates that appearance.

---

# 7. Prefix

Prefix means:

Beginning part of key.

Example:

```text
dataset/Cat/cat1.jpg
dataset/Cat/cat2.jpg
dataset/Cat/cat3.jpg
```

Common prefix:

```text
dataset/Cat/
```

AWS groups objects using prefixes.

This creates virtual folders.

---

# 8. How We Used S3

We uploaded:

```bash
aws s3 cp \
dataset/ \
s3://maaz-animal-classifier-01/dataset/ \
--recursive
```

What happened?

AWS:

```text
Read Local Files
↓
Create Object Keys
↓
Upload Objects
```

Example:

Local:

```text
dataset/Cat/1.jpg
```

became:

```text
dataset/Cat/1.jpg
```

inside S3.

---

# 9. Downloading From S3

We used:

```bash
aws s3 cp \
s3://maaz-animal-classifier-01/dataset/ \
dataset/ \
--recursive
```

AWS:

```text
Read Objects
↓
Download
↓
Create Local Files
```

# 11. Durability

AWS advertises:

```text
11 Nines Durability
```

Meaning:

```text
99.999999999%
```

Extremely durable.

Practical meaning:

Losing data is extremely unlikely.

AWS replicates data automatically.

---

# 12. Availability vs Durability

Many engineers confuse these.

---

## Durability

Can data survive?

Example:

```text
Disk Failure
```

If data still exists:

Durability is high.

---

## Availability

Can I access data right now?

Example:

```text
Service Outage
```

Data exists.

But inaccessible temporarily.

Availability issue.

---

# 13. S3 Storage Classes

AWS offers multiple storage classes.

---

## Standard

Most common.

Use for:

```text
Active Datasets
Active Models
```

---

## Standard-IA

IA:

```text
Infrequent Access
```

Cheaper storage.

Higher retrieval cost.

---

## Glacier

Very cheap.

Used for:

```text
Archives
Backups
```

Retrieval takes longer.

---

# ML Example

Dataset used daily:

```text
S3 Standard
```

Old archived dataset:

```text
Glacier
```

# 14. S3 Versioning

Imagine:

```text
best_model.pth
```

uploaded today.

Tomorrow:

```text
best_model.pth
```

uploaded again.

Without versioning:

```text
Old File Lost
```

With versioning:

```text
Version 1
Version 2
Version 3
```

all preserved.

---

# Why MLOps Teams Love Versioning

Models evolve.

Example:

```text
v1
v2
v3
v4
```

Versioning protects against mistakes.

---

# 15. Lifecycle Policies

Suppose:

```text
10 TB Logs
```

generated every month.

Keeping everything in Standard storage is expensive.

Lifecycle Rules:

```text
30 Days
↓
Move To IA

90 Days
↓
Move To Glacier
```

Automatic cost optimization.

# 18. Common S3 Commands

List Buckets:

```bash
aws s3 ls
```

---

List Objects:

```bash
aws s3 ls s3://bucket-name/
```

---

Upload Single File:

```bash
aws s3 cp file.txt s3://bucket/
```

---

Upload Directory:

```bash
aws s3 cp dir/ s3://bucket/ --recursive
```

---

Download File:

```bash
aws s3 cp s3://bucket/file.txt .
```

---

Download Folder:

```bash
aws s3 cp s3://bucket/dir/ local_dir/ --recursive
```

# 21. Common Beginner Mistakes

Mistake 1:

Thinking folders are real.

They are prefixes.

---

Mistake 2:

Making buckets public.

Security risk.

---

Mistake 3:

Not enabling versioning.

Can lose important models.

---

Mistake 4:

Using Glacier for active datasets.

Retrieval becomes slow.

---

Mistake 5:

Treating S3 like a local filesystem.

S3 is object storage.

Different design.

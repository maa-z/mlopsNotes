# Chapter 5 — AWS CLI Deep Dive

# 1. Why AWS CLI Matters

Throughout our project, we repeatedly used:

```bash
aws s3 cp
aws s3 ls
aws configure
```

At first these look like simple commands.

But behind those commands is one of the most important tools in AWS:

```text
AWS CLI
(AWS Command Line Interface)
```

If AWS Console is:

```text
Clicking Buttons
```

then AWS CLI is:

```text
Infrastructure Through Commands
```

Professional ML Engineers, DevOps Engineers, and MLOps Engineers use AWS CLI extensively.

---

# 2. What Is AWS CLI?

AWS CLI is a tool that allows your computer to communicate with AWS services.

Think:

```text
Laptop
↓
AWS CLI
↓
AWS APIs
↓
AWS Services
```

Without AWS CLI:

```text
Manual Console Clicking
```

With AWS CLI:

```text
Automation
Scripting
CI/CD
MLOps Pipelines
```

---

# 3. The Hidden Truth

When you run:

```bash
aws s3 ls
```

AWS CLI does NOT directly talk to S3.

Instead:

```text
AWS CLI
↓
AWS API Request
↓
S3 Service
↓
Response
```

Everything in AWS ultimately happens through APIs.

AWS CLI is simply a user-friendly wrapper around those APIs.

# 6. Where Are Credentials Stored?

Many beginners think:

```text
AWS Stores Credentials Somewhere Online
```

Wrong.

AWS CLI stores credentials locally.

Linux:

```text
~/.aws/
```

Contains:

```text
credentials
config
```

---

# credentials File

Example:

```ini
[default]
aws_access_key_id=XXXX
aws_secret_access_key=YYYY
```

---

# config File

Example:

```ini
[default]
region=ap-south-1
output=json
```

---

# 7. What Happens During aws configure?

Step 1:

```text
Store Credentials Locally
```

Step 2:

```text
Store Default Region
```

Step 3:

```text
Store Output Preference
```

Step 4:

```text
Future Commands Use These Settings
```

# 8. Access Key vs Secret Key

These came from IAM.

Remember:

Authentication:

```text
Who Are You?
```

AWS CLI uses:

```text
Access Key
Secret Key
```

to prove identity.

Think:

```text
Access Key
=
Username

Secret Key
=
Password
```

---

# 9. Never Share Secret Keys

Bad:

```python
secret_key = "ABC123"
```

inside code.

Very dangerous.

If leaked:

```text
Attacker Can Use Your AWS Account
```

Potential consequences:

```text
Massive Bills
Resource Deletion
Security Breach
```

# 14. Uploading Directories

Directory:

```bash
aws s3 cp folder/ s3://bucket/ --recursive
```

---

Why Recursive?

Because:

```text
Folder
↓
Contains Many Files
```

AWS must upload all contents.

---

# Example

Dataset upload:

```bash
aws s3 cp \
dataset/ \
s3://maaz-animal-classifier-01/dataset/ \
--recursive
```

This uploads:

```text
Cat Images
Dog Images
Subdirectories
Everything
```

# 17. Sync Command

Most beginners use:

```bash
cp
```

Professionals often use:

```bash
sync
```

Example:

```bash
aws s3 sync \
dataset/ \
s3://bucket/dataset/
```

Difference:

```text
Only Changed Files Transfer
```

Much faster.

---

# 18. Why Sync Matters In MLOps

Imagine:

```text
1 TB Dataset
```

You modify:

```text
1 Image
```

Using:

```bash
cp --recursive
```

could recheck everything.

Using:

```bash
sync
```

transfers only differences.

Huge time savings.

# 21. Credential Resolution Chain

This is a senior-level topic.

When AWS CLI needs credentials:

It checks multiple locations.

Simplified order:

```text

↓
AWS Credentials File
↓
IAM Role
```

First valid credentials win.

# 26. Common Beginner Mistakes

Mistake 1:

Forgetting:

```bash
aws configure
```

Result:

```text
Unable to locate credentials
```

---

Mistake 2:

Wrong region.

Resources appear missing.

---

Mistake 3:

Missing:

```text
--recursive
```

Only one file uploads.

---

Mistake 4:

Committing credentials to GitHub.

Huge security risk.

---

Mistake 5:

Using Root Account credentials.

Never do this.

Use IAM users or roles.
